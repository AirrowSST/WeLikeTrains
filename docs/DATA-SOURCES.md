# Sources, licences and data handling

Current implementation details and remaining limitations are tracked in [ROUTING-DATA-STATUS.md](ROUTING-DATA-STATUS.md). DataMall stop sequences and distances now drive the bus graph independently of OSM bus shapes; unmatched shapes are explicitly schematic. OSM still supplies walking and rail geometry. Additional bundled official layers are TrainStationExit, CoveredLinkWay and CyclingPath (`data/lta-geospatial.json.gz`); released planned bus changes use `data/planned-buses.json.gz`. Their provenance records source, access time, licence and hashes. Optional OSM bus-shape joins and conservative traffic corrections are local computations; they are not measured vehicle travel times, and schematic legs are excluded from road-specific spatial effects.

No Telegram/web-page scraping is used. No private commuter data was acquired. Public landmarks in the catalog are demo endpoints, not real residents’ addresses. Online map display requests visible OneMap tiles; this necessarily exposes the client IP address and requested tile coordinates to SLA’s service. When configured in normal mode, Wayce's search UI sends typed place searches to Google and requests display name, formatted address and location for the selected prediction. Predictions are not cached; Wayce does not persist search drafts or use Google routing. Bus-stop markers use the bundled DataMall reference snapshot. Indexed fallback search and route computation use bundled local files, and the app falls back to its bundled vector map when OneMap is unavailable. No advertising or analytics layer is loaded. Web fonts are bundled locally. Lucide icons, Leaflet, React and other packages retain their published licences in npm dependencies; consult the lockfile for exact versions.

## OSM provenance and refresh

`data/OSM-PROVENANCE.json` records extraction time, source, bounding box and query; `scripts/import-osm.mjs` contains the exact bounded split queries and station-code join. The snapshot is WGS84: network coordinate tuples are latitude/longitude, GeoJSON is longitude/latitude. The organiser’s missing station polygon file was not used, and its CRS was not guessed.

`npm run data:osm` is a **manual maintenance command**, not part of app startup, build or CI. It reuses `.cache` and spaces new bounded downloads. For a fresh extract, archive the specific cache files deliberately or use a new checkout; do not repeatedly query a public Overpass server. Respect its load policy or use a managed/self-hosted endpoint (`OVERPASS_URL`) for large refreshes. The running application never contacts Overpass or public routing providers. In configured normal mode, Wayce renders the search interface and requests attributed predictions through Google Place Autocomplete; OneMap supplies visual tiles. Cloud Run serves the committed OSM vectors and the backend loads the committed routing graph directly.

The derived extract includes all fetched supported rail route relations and selected buses (2, 12, 17, 27, 34, 36, 67, 118, 190, 196); unmapped, future or incomplete services are not a promise of operational service. Rail names/codes can change. Retain attribution and the ODbL obligations when redistributing modified database files. App code licensing is left to the repository owner; no third-party data ownership is claimed.

## LTA bus-reference provenance and refresh

`data/bus-network.json.gz` is a compact normalized copy of every row returned by
DataMall BusStops, BusRoutes and BusServices on the recorded access date.
`data/BUS-NETWORK-PROVENANCE.json` records endpoint URLs, access time, licence,
counts, missing stop joins and a SHA-256 hash. It contains no AccountKey. The
2026-09-19 import contains 5,208 stops, 26,823 ordered route-stop rows and 801
service directions, with zero route rows referring to a missing stop.

`npm run data:buses` is an **explicit authenticated maintenance command**. It
walks each official endpoint sequentially in 500-row `$skip` pages, validates and
sorts the records, then replaces the snapshot and provenance. The app never
downloads these bulk tables at startup, during tests or per request. Cloud Run
receives the snapshot through the existing container `data/` copy; deploying a
new snapshot remains a separate, explicitly authorised operation. The map uses
the full official stop/service index, while planner geometry remains limited to
the selected OSM bus relations until those official stop sequences have been
joined to verified road geometry.

## LTA train-schedule provenance and refresh

`data/train-schedule.json.gz` is a compact derived copy of the official train GTFS Schedule. `data/GTFS-PROVENANCE.json` records its access time, service-date coverage, source endpoint, licence, counts and SHA-256 hash. It contains no AccountKey or expiring signed download URL. The committed snapshot may be copied, modified and distributed under the Singapore Open Data Licence v1.0 with the attribution above; Wayce does not imply LTA endorsement.

`npm run data:gtfs` is an **explicit authenticated maintenance command**. It calls the metadata endpoint once, follows the short-lived archive link, validates the required GTFS files, normalizes them and replaces the snapshot plus provenance. The app never downloads the bulk schedule at startup, during tests or per request. When a requested date or rail leg is absent, the planner labels and uses its local distance estimate instead. GTFS values are planned times, not proof of actual train movement or an accuracy claim.
